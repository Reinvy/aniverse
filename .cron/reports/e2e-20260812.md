## Summary

E2E Navigation & UI Integration Testing cycle (C4) — 2026-08-12.

### What was changed
- **`src/lib/spatial-store.tsx`** — hash-anchor deep linking for the spatial canvas landing page:
  - `sectionFromHash()` maps URL hashes (`#features`, `#pricing`, `#showcase`, `#faq`, `#hero`) to spatial sections
  - On mount, the provider reads `window.location.hash` and opens the matching section instead of always hero
  - `hashchange` listener keeps deep links working after in-page hash changes
  - `history.replaceState` sync keeps the URL hash in line with the active section (no history spam)
  - **Fixes broken header nav**: `MAIN_NAV_LINKS` (Features → `/#features`, Pricing → `/#pricing`) previously landed on the hero node when clicked from any non-landing page — the anchor did nothing because the canvas is a section-navigator, not scroll anchors
- **`e2e/navigation.spec.ts`** (+4 tests, 77 lines):
  - `/#features` deep link opens the Features node ("AI-Powered Generation" visible)
  - `/#pricing` deep link opens the Pricing node ("MOST POPULAR" badge + `// TIER` labels)
  - Header nav links from `/characters` + `/blog` navigate to the correct landing section
  - ScrollToTop (PR #114) appears after scrolling on `/characters` and returns to top

### Why
- The 3 new deep-link tests FAILED against production before the fix (73 passed / 3 failed) — proving the header's `/#features` and `/#pricing` links were dead anchors landing on hero. This is the app's main cross-page navigation path, so it was a real integration bug, not a test artifact.
- The ScrollToTop test passed against production — verifying PR #114's new component ships correctly (regression guard).
