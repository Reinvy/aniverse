## Bug Found & Fixed

### Flaky Test: `navigation.spec.ts` — "should have working header navigation"

**Root cause:** The navigation test on the landing page header clicks each nav link and asserts the URL matches the `href`. The header contains "Gallery" (`/dashboard/gallery`) and "Marketplace" (`/dashboard/marketplace`) which are protected routes. When the test runs without a logged-in session, these links redirect to `/login`, causing a URL mismatch with the expected `href` regex. The test passed only when session state happened to be present, making it flaky.

**Fix applied:**
- Added `PROTECTED_ROUTES` constant listing auth-required dashboard routes
- When a nav link targets a protected route, the test now asserts the URL is `/login` (the expected redirect behavior) instead of the original href
- Public routes continue to assert exact URL matching as before

**Files changed:**
- `e2e/navigation.spec.ts` — 13 insertions, 2 deletions
